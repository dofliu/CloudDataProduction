# 使用說明(完整操作手冊)

> 對象:第一次接觸本平台的**老師與助教**(學生連線操作見 [連線教學.md](連線教學.md))。
> 內容涵蓋:啟動、網頁各分頁、教師操作、學生可寫控制(CNC 刻字 / 手臂取放)、
> 產線物料流、自然語言建廠、常見問題。
> 更新:2026-07-30。

## 1. 啟動平台

### 1.1 需求

- Windows / Linux 皆可;Python 3.11、Node 20(只有要跑前端開發模式才需要 Node)。
- 第一次安裝:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt   # Windows
# Linux: python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env        # 依需要調整(教師 token、埠、場景檔)
cd web && npm ci            # 前端(要跑 dev 模式或重建 dist 才需要)
```

### 1.2 啟動後端(引擎 + API + 三協定)

```powershell
.\run.ps1                   # Windows 一鍵(自動用 .venv 的 python 跑 main.py)
# 或
python main.py              # 直接跑(記得用 venv 的 python)
```

同一個進程會起:模擬引擎、REST API(`API_PORT`,預設 8077)、WebSocket、
Modbus(6020)/ OPC-UA(6041)/ MQTT(6083)、Historian。
場景由 `.env` 的 `SCENARIO_FILE` 決定(預設 `scenarios/p0_single_cnc.yaml`;
課堂請改 `scenarios/default_park.yaml` 或 `scenarios/class_park.yaml`)。

### 1.3 開網頁

兩種方式擇一:

| 方式 | 做法 | 適用 |
|------|------|------|
| **開發模式** | `cd web && npx vite` → 開 `http://localhost:5173` | 平時開發、改前端 |
| **同源部署** | `cd web && npm run build`,`.env` 設 `STATIC_DIR=web/dist` → 直接開 `http://<主機>:8077` | 課堂常駐(一個埠涵蓋網頁+API+WS) |

> ⚠ 開發模式的 vite 會把 `/api` 與 `/ws` 代理到 `127.0.0.1:8077`
> (`web/vite.config.ts`)。若你的 `.env` 改了 `API_PORT`,vite 的 `BACKEND` 也要跟著改,
> 否則網頁一片空白、終端機一直跳 `ECONNREFUSED`。

### 1.4 登入

- **教師 / 管理員**:登入卡片展開「▸ 老師 / 管理員以 token 進入」,輸入 `.env` 的
  `TEACHER_TOKEN`。教師可用所有分頁與控制。
- **學生**:用老師發的帳號密碼登入(帳號管理在教師控制台);學生只能寫**自己認領公司**的設定點。
- `.env` 未啟用身分驗證時(開發環境)大多數操作放行。

## 3. 學生可寫控制(設定點)

設定點是平台上**唯一開放學生寫**的東西(量測唯讀、線圈教師才可寫)。
三條路徑等價:**網頁詳情彈窗**、`POST /api/devices/{id}/setpoint`、**Modbus FC06**。
寫入一律後端夾限到範圍,越界自動 snap 回。

### 3.1 CNC:刻字文字 + 轉速 + 圖樣

| 設定點 | 範圍 | 說明 |
|--------|------|------|
| `spindle_rpm_setpoint` | 2000~12000 rpm(reg 100) | 主軸轉速目標 |
| `machining_pattern` | 0~2(reg 101) | 0=刻字 / 1=圓 / 2=方 |
| `engrave_char_1..8` | ASCII 碼(reg 102..109) | 刻字內容,每格一字(0=空白) |

**刻字操作**(pattern 0 生效,支援 A–Z / 0–9 / 空白 / `-`,最多 8 字,預設 NCUT):

- 網頁:詳情彈窗 → 設定點區的 **`engrave_text` 文字框**直接打字按「寫入」。
- REST:`POST /api/devices/{id}/engrave_text {"text":"HI42"}`(一次寫進 8 格)。
- Modbus:FC06 對 reg 102..109 逐格寫 ASCII 碼(H=72、I=73、4=52、2=50,其餘寫 0)。

新文字從**下一件工件**開始刻(換件時刻痕清空);面板 TEXT 列與 3D 刻痕即時對應。

### 3.2 六軸手臂:指定取放兩點(A 夾取 → B 放下)

| 設定點 | 範圍 | 說明 |
|--------|------|------|
| `pick_x` / `pick_y` | ±1250 mm(reg 100/101) | 夾取點(地面座標) |
| `place_x` / `place_y` | ±1250 mm(reg 102/103) | 放置點 |

引擎用逆運動學把兩點解回六軸角度;學生讀 `tcp_x/y/z` 可驗證下探時真的到了寫入的座標。
**負值走 int16 二補數**(例 −820 → raw 64716)—— 這是真實 Modbus 的常見坑,刻意保留作教學。
畫面裡的取放料檯會跟著設定點移動。

## 4. 產線物料流(工件真的在設備間流動)

公司場景 YAML 有 `line:` 宣告(例 `line: [cnc-a, arm-1, cnc-b]`)時,引擎維護真實的工件傳遞:

```
上游完工 → 出料緩衝(待取)→ 手臂取放(一次一件)→ 下游入料緩衝(待加工)→ 下游加工
                                              └→ 終站輸送帶:上帶 → 走完帶長 → 出貨
```

誠實規則(全部反映在資料上,不只是畫面):

- 出料緩衝滿(3 件)→ **上游停機等待**;下游無料 → **下游待機**(都算 no-demand,不罰 OEE 可用率)。
- 手臂**事件驅動**:有件才跑取放循環,`cycle_count` = 實際搬運件數;無料時在取件點上方待命
  (state=idle、電流掉回保持電流)。
- 終站輸送帶**帶上沒工件就停**(belt_speed→0,不空轉);工件走完帶長(8 sim 秒)才算出貨。

**可觀測**:產線設備多了 FC04 點位 `line_out_buffer` / `line_in_buffer` / `line_on_belt`
(位址見目錄);整條產線的即時帳在 WS telemetry 的 `lines` 欄。
廠內 3D 視圖把「待取」堆畫在手臂取件點、「待加工」在放件點,輸送帶只畫帳上的件數,
左下角有「已出貨 N 件 · 累積搬運 N 件」統計。

### 4.1 🎬 慢速觀察(怎麼「看見」取放動作)

×120 加速下,一個手臂循環只有 0.07 牆鐘秒 —— 離散動作**物理上不可見**,不是動畫故障。
教師在廠內產線視圖左下角按「**🎬 慢速觀察 ×2**」,sim 倍率降到 ×2:
「完工 → 待取 +1 → 手臂取件 → 放上輸送帶 → 送出出貨」全程用真實資料自然呈現;
看完按「**⏩ 恢復 ×120**」。(等同教師控制台的時鐘倍率控制。)

### 4.2 哪些公司有產線?

由場景產生器自動配置:配方中出現「producer + 手臂 + (producer 或輸送帶)」就接線,
公司介紹會寫明「產線:… 工件在引擎內真實流動」。課堂版 65 廠有 12 條、示範版 37 廠有 6 條
(含教師示範廠 c65:雙 CNC 夾手臂)。要調整改 `scenarios/scripts/gen_*.py` 再重跑,勿手改 YAML。

## 5. 教師操作

### 5.1 教師控制台

- **故障注入**:選設備 / 故障類型(sudden / gradual / intermittent / cascading / sensor_*)/
  嚴重度 / 生效時間;「⚡ 快速故障」給課堂 demo。
- **情境腳本**:套用 `scenarios/course_weeks.yaml` 的每週情境、災難日腳本。
- **🏭 建廠(自然語言)**:輸入描述 → 即時加一間公司(免重啟,三協定即時上線)。
  - 規則式(免 API key、離線):支援**多型別**,如「建一間叫 智造示範 的公司,有 2 台 CNC 和 1 支機械手臂」。
  - 設 `GEMINI_API_KEY` 走 LLM,可理解自由描述;失敗自動回退規則式。
  - 產出的設備組合能接產線就**自動接上物料流**。
- **時鐘**:調 sim 倍率 / 暫停。
- **🧹 重置課堂資料**:換班歸零(不刪 DB)。

### 5.2 常用 API(教師 token)

```bash
TOKEN="Authorization: Bearer <TEACHER_TOKEN>"
curl -X POST http://<主機>:8077/api/factory -H "$TOKEN" -H "Content-Type: application/json" \
  -d '{"description":"建一間有 2 台 CNC 和 1 支機械手臂的公司"}'
curl -X POST http://<主機>:8077/api/devices/<id>/engrave_text -H "$TOKEN" \
  -H "Content-Type: application/json" -d '{"text":"HI42"}'
curl -X POST http://<主機>:8077/api/sim/clock -H "$TOKEN" \
  -H "Content-Type: application/json" -d '{"multiplier":2}'
```

> ⚠ Windows PowerShell 會弄壞 `curl -d '{json}'`,POST 請用 Python / 網頁 UI。

### 5.3 離線備援資料包(W4 Plan B)

網路 / 平台出狀況時的整堂課備案 —— 預先產好、發給學生即可離線上課:

```bash
python tools/make_offline_pack.py --zip
# → offline_pack/:11 種產業各一台、7 sim 天(1 分鐘取樣)乾淨基線資料
#   每台 CSV + JSON、catalog.json(規格書)、manifest.json(seed/commit 可溯源)、README.txt
```

W4 的敘述統計 / 分佈 / 日週期活動全部可在這包上完成。同參數重產得到完全相同的資料。

### 5.4 MCP(Claude Desktop)

`python mcp/server.py` 掛到 Claude Desktop,可用自然語言查園區 / 注入故障 / 建廠(見 [06-mcp.md](06-mcp.md))。

## 6. 學生連線(摘要)

完整圖文見 [連線教學.md](連線教學.md)。重點:

- 設備目錄(`/api/catalog` 或網頁「設備目錄」)是**規格書**:每台的協定 / 埠 / unit_id /
  各點位位址都在上面,照抄就能連。
- Modbus 四種 object type:holding(FC03,量測)、discrete input(FC02,狀態 bit)、
  input register(FC04,含 ×100 縮放鏡像與**產線緩衝**)、coil(FC01 讀;FC05 教師寫)。
- 設定點:FC06 寫單一暫存器(見本文 §3)。
- 範例程式:`student_kit/p0_modbus_reader.py`(入門)、`p1_modbus_objecttypes.py`(四 object type)、
  `dashboard/` 與 `dashboard_simple/`(自建監控台,三協定)。

## 8. 常見問題

| 症狀 | 原因與解法 |
|------|------------|
| 網頁空白、vite 終端一直 `ECONNREFUSED 127.0.0.1:8077` | 後端沒開,或 `API_PORT` 與 vite 代理不一致 → 起 `run.ps1`、對齊埠(§1.3) |
| 點設備看不到可輸入的設定點 | 前端版本太舊 → `git pull` 後 dev 模式直接生效;同源部署要 `npm run build` |
| 寫設定點回「請先登入」 | `.env` 啟用了 auth → 教師 token 或已認領該公司的學生帳號 |
| 手臂座標寫負值沒反應(Modbus) | int16 要寫二補數:−820 → 64716(REST / 網頁不用管) |
| 機台不動、柱燈黃 | 看 state:被教師停機(stopped)按 ▶ 復機;產線餓料 / 滿料是正常等待;班表下班時段本來就休 |
| 看不到手臂取放動作 | ×120 下物理上不可見 → 產線視圖按「🎬 慢速觀察 ×2」(§4.1) |
| 輸送帶不動 | 產線終站帶上沒工件就是停的(誠實行為);上游停線它也會停 |
| `python` 直接跑就崩 | 用了全域 Python → 一律 `run.ps1` / venv 的 python |
| 建廠回 422 | 描述解析不出設備型別 → 寫「N 台 <機種>」;PowerShell 的 curl JSON 問題見 §5.2 |
