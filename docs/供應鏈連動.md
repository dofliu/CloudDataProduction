# 跨公司供應鏈 —— 你的產出是別人的進料

> 對應 `engine/supply.py`、`scenarios/scripts/gen_class_park.py` 的 `build_supply_chain()`、
> `web/src/student/SupplyPanel.tsx`、`web/src/teacher/SupplyImpact.tsx`。
> 驗證:`tests/test_supply_chain.py`。

## 這一層解決的問題

`engine/line.py` 已經讓工件在**一間公司內**真實流動(CNC → 手臂 → CNC)。但 60 個人各自守著
自己那間廠,彼此沒有關係 —— 你的機台壞不壞,對別人完全沒有影響。

接上供應鏈之後:

- **你上游那位同學的機台壞了沒人管,你的產線就餓料停機。**
- **你自己停太久,下游同學的進料倉會塞爆,反過來把你卡住。**

這是全班第一次感覺到彼此存在,也正好是「雲端生產 / 雲製造」那章的活教材:
供應鏈可視性、單一供應商風險、長鞭效應,不用比喻,現場就在跑。

## 場景怎麼宣告

park 層(與 `companies:` 同層):

```yaml
supply_chain:
  - {from: c01, to: c02, part: "精加工件", cap: 45, initial: 18, external_backup_h: 3.0}
```

| 欄位 | 意思 |
|---|---|
| `cap` | 客戶端進料倉容量。塞滿 → 供應商出貨端阻塞 |
| `initial` | 開場庫存(不然開學第一分鐘全班一起餓料) |
| `external_backup_h` | 缺料超過這麼多**模擬小時**,外部備援供應商補一件。`0` / 省略 = 沒有備援 |

`scenarios/class_park.yaml` 由 `gen_class_park.py` 產生:把**做得出零件的**公司每 4 間串成
一條鏈(64 廠 → 10 條鏈、32 條供應關係)。

- **為什麼是 4 而不是全班一條長鏈**:一條 64 節的鏈只要有人停機,後面 60 個人全陪葬,
  那不是教學是連坐。4 節剛好等於課堂分組大小,斷鏈的因果也還看得清楚。
- **為什麼跳號**:中間跳過的是沒有 producer 的廠(電表 / 壓縮機 / 風機那類)。
  它們本來就不是在做零件,硬接進去只會在啟動時噴一堆略過警告。
- 每條鏈的**最後一段刻意不給外部備援**,當對照組:有備援的那幾段會看到「靠外購撐著」,
  沒備援的那段上游一停就真的死給你看。
- 想讓班上耦合鬆一點,把生成器裡的 `CAP` 調大再重跑(**不要手改 YAML**)。

## 外部備援為什麼存在

不是為了讓資料好看。是為了讓「單一供應商風險」可以被**量化**:平台分別記
`delivered`(上游同學供的)與 `purchased`(外部備援補的),算出**自給率**。
誰的廠長期靠外購撐著,教師面一眼看得出來 —— 那代表他上游那位同學該被關心了。

沒有備援的鏈整條會真的停,那也是誠實的結果。教師可以刻意留幾條當對照。

## 計帳原則(跟 line.py 一致)

**餓料與阻塞都不罰 OEE 可用率。** 餓料不是設備的錯 —— 它降的是**產出**,學生會在
產量與稼動上看見。可用率的分母只算「排程要它產出卻沒產出」(見 `device._accumulate_oee`)。

這條有測試守著(`tests/test_supply_chain.py` 第 4 項):餓料期間 `down_h` 不增加、
可用率不下降。

守恆也有測試:下游吃掉的件數 ≤ 上游供的 + 外部買的 + 開場庫存,工件不會憑空出現。

## 誰算供應商 / 誰算客戶

| 情況 | 產出看什麼 | 消耗看什麼 |
|---|---|---|
| 公司有 `line:` 宣告 | 那條產線的 `shipped` | **首站**的完工數(它吃原料) |
| 公司沒有 `line:`(一人一廠常見) | 所有 producer 的累積量 tag 總和 | 同左 |

兩種情況都不另設事件通道,直接讀學生從 Modbus 讀得到的同一組累積量
(鐵則二:同一份資料,不做兩套)。

## API

| 方法 | 路徑 | 說明 |
|---|---|---|
| GET | `/api/supply` | 所有供應關係 + 目前的餓料 / 阻塞連鎖反應 |
| GET | `/api/supply/{company}` | 我等誰的料、誰在等我 |

world snapshot 也帶 `supply`(WebSocket / historian 都看得到)。

## 課堂怎麼用

- **W1 導論**:講「雲端生產」的第二種斷句(雲製造)時,直接投影供應鏈連鎖反應表。
- **W6 異常**:某人的設備被注入故障 → 下游三個人的產出一起掉。找兇手變成全班的事。
- **W11 KPI**:你的 OEE 掉了,是你自己的問題還是上游的問題?用 `starved_h` 分得出來。
- **期末專題**:供應鏈韌性分析(自給率、斷鏈時間、緩衝大小對產出的影響)是現成題目。

不想用的時候,把場景的 `supply_chain:` 拿掉(或用 `default_park.yaml`),
一切行為與導入前完全一致 —— 沒有宣告就沒有任何額外邏輯生效。
